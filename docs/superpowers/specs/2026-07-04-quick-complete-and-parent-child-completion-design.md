# 快捷完成任务 + 父子联动完成 + 标记偏移修复

## 概述

三个关联改动：
1. 修复甘特图任务列表标记偏移问题
2. 增加快捷完成按钮（甘特图 + 侧边栏）
3. 完成父任务时联动子任务，含阻塞/外部依赖预警

## 一、标记偏移修复

**文件**: `src/components/gantt/GanttTaskPanel.tsx`

**问题**: 第 83 行 `const indent = depth * 16 + (hasChildren ? 0 : 18)` 导致同层级有子任务和无子任务的任务优先级标记水平位置不一致。

**修复**: 去掉 `hasChildren` 条件，统一为 `const indent = depth * 16`。

**影响**: 无子任务的项目标记向左移动 18px，与同层级有子任务的项目对齐。甘特图条位置不受影响（indent 仅影响左侧任务面板内的标记和标题）。

## 二、快捷完成按钮

### 位置

- **甘特图**: `GanttTaskPanel.tsx` 任务行右侧
- **侧边栏**: `Sidebar.tsx` 的 `TaskNode` 组件行右侧

### 交互

- 行容器添加 `group` 类，按钮使用 `opacity: 0 group-hover:opacity-100 transition-opacity` 控制显隐
- `status === 'done'` 的任务不显示按钮
- 点击调用 `updateTask.mutate({ id, status: 'done' })`
- 如果任务有子任务（未完成），弹出确认对话框（见第三节）
- 如果任务无子任务，直接完成，无弹窗
- 错误处理：`onError` 回调中 `alert(error.message)`

### 注意事项

- 甘特图行和侧边栏 TaskNode 行目前均无 `group` 类，添加时不会嵌套
- 已完成任务不显示按钮，保持简洁

## 三、父子联动完成 + 阻塞预警

### 触发时机

快捷完成按钮点击时，检测目标任务是否有未完成子任务（递归后代）。

### 决策树

```
点击快捷完成
  ├── 无未完成子任务 → 直接完成
  └── 有未完成子任务 → 弹出三按钮确认弹窗
        ├── [同时完成所有子任务] → 批量完成父 + 所有後代
        ├── [仅完成此任务] → 仅完成父任务
        └── [取消] → 不操作
```

### 后代收集

递归遍历 `task.children` 树，收集所有 `status !== 'done'` 的后代任务（包括子、孙、曾孙等），存储为 `Task[]`。

### 外部依赖判断

1. 收集父任务的所有后代 ID 集合（包括已完成的后代，用于判断依赖范围）
2. 遍历每个未完成子任务的 `depends_on` 数组
3. 排除已完成的依赖任务（已完成的依赖不构成阻塞）
4. 对于每个未完成的依赖 ID，检查是否在后代 ID 集合内
5. 不在集合内 → 标记为"外部依赖"

### 阻塞子任务处理策略

**策略**: 允许完成，但充分告知。

在 confirm 弹窗中明确展示：
- 未完成子任务总数
- 阻塞子任务数量
- 其中依赖外部任务的数量

用户自行决定是否批量完成。理由：父任务完成意味着整条工作线结束，阻塞子任务继续挂着无意义；通过信息透明化让用户决策。

### confirm 弹窗文案

**简单情况**（无阻塞子任务）：
```
该任务有 N 个未完成子任务。是否同时完成所有子任务？
```

**复杂情况**（有阻塞子任务）：
```
该任务有 N 个未完成子任务，其中 M 个处于阻塞状态（K 个依赖外部任务）。是否同时完成所有子任务？
```

按钮：`[同时完成所有子任务]` `[仅完成此任务]` `[取消]`

### 弹窗实现

- 采用自定义组件，参考 `DetailPanel.tsx` 中保存确认弹窗的样式（`bg-background/80 backdrop-blur-sm` + `bg-popover shadow-lg rounded-xl`）
- 作为独立组件 `ConfirmDialog` 放在 `src/components/ui/` 下
- 通过回调函数传递用户选择结果

### 批量完成逻辑

用户选择"同时完成所有子任务"后：
1. 收集所有需要完成的任务 ID 列表（父任务 + 所有未完成後代）
2. 使用 `Promise.all` 或串行调用 `updateTask.mutate` 逐个更新
3. 任一失败则 `alert` 错误信息，已成功的任务保持已完成状态

## 五、边界情况

1. **已完成依赖**: 判断外部依赖时排除 `status === 'done'` 的依赖，不误报
2. **循环依赖**: 不做特殊处理。如果存在循环依赖，`depends_on` 中的任务不会在后代集合中，会被标记为"外部依赖"，在 confirm 中展示给用户判断
3. **空子任务**: 如果所有子任务均已完成，快捷按钮点击直接完成父任务，无弹窗
4. **深度嵌套**: 递归收集后代，深度不受 MAX_DEPTH 限制（已完成分区中的任务也可能有子任务）
5. **并发安全**: 批量完成时顺序执行，每个 `mutate` 独立处理错误，不因一个失败而回滚
